## 1. 项目定位

### 1.1 这是什么

一个 **VOCALOID Music Creator / 二创剪辑作者** 的个人官方网站。

三条身份主线，在网站上并列呈现：

| 身份 | 表述 | 说明 |
|---|---|---|
| 主身份 | **Vocaloid Music Creator** | 站点核心，权重最高 |
| 副身份 | **二创剪辑作者** | 过往积累，有大爆作，是引流主力 |
| 虚拟角色 | **メキチャン（mekichann）** | 破軍星の終焉煌めき的自设，视觉与叙事载体 |

> **命名约定（重要）**
> 角色自设名为 **メキチャン（mekichann）**。
> **キメラ（kimera）** 是角色的**性别**设定，源自重音テト的性别，亦代表本人性别为中性（偏女）。
> 两者不可混用：名称用「メキチャン」，性别用「キメラ」。
> 英文/罗马音一律写 **mekichann**，不写 chimera（这是性别）。

### 1.2 目标

- **短期**：把已有的二创爆作沉淀成一个能长期挂着的作品档案，替代散落的平台主页
- **长期**：以 Vocaloid Music Creator 的身份接到稳定的合作与委托

### 1.3 目标观众

| 优先级 | 人群 | 他们想找什么 |
|---|---|---|
| 1 | Vocaloid 圈听众 / 同人创作者 | 「这人做过什么，值得关注吗」 |
| 2 | 潜在合作方（作曲、词、曲绘、动画） | 「作品质量如何，怎么联系」 |
| 3 | **以前动漫剪辑时的粉丝** | 「当年那个剪辑作者现在还在做吗」 |
| 4 | 国内泛二次元听众 | 「二创好不好看，VOCALOID曲好不好听，能不能一键播放」 |

> 第3 类观众是**回流流量**的主要来源。他们可能不认识现在的你，但认得出你以前的作品。
> 因此 WORKS 页的二创分类与「全部制作 / 部分制作」标记对他们尤其重要——
> 「全部制作」是最强的信任信号。

### 1.4 站点基调

定位为**作品档案馆（Archive）/个人宣传介绍**
访客进来是「看和听」，不是「被营销」。

## 2. 设计风格总结

### 2.1 风格关键词

> 提炼自设定图上的自设关键词：`White / Black / Dark / Music / Red / Shine`

| 关键词 | 含义 | 在设计中的落地 |
|---|---|---|
| **White** | 主体留白 | 大面积负空间，页面呼吸感 |
| **Black** | 硬边黑色 | 纯黑 `#08080A`，文字与分割线 |
| **Dark** | 暗部厚重 | 深灰阶层次，图片去饱和处理 |
| **Music** | 音乐性 | ECG 波形线贯穿全站，等宽字体标注 BPM/调性 |
| **Red** | 唯一彩色 | 点缀色或强调色 |
| **Shine** | 白色高光溢出 | 文字发光、图片边缘光、hover 微光 |

补充意象关键词：**終焉**（终结）、**煌めき**（闪耀）、**破軍星**（白虎座凶星）、**キメラ**（性别设定）、**ゴシック**（哥特街头机能）。

**站点个性签名（sig）**

> **「終焉は、最も美しく煌めく。」**
> （終焉は、最も美しく煌めく。）

这条签名贯穿全站：Footer、404 页、TEXT OF THE TOP 首屏文案、SHARE 卡片。
它是「終焉」与「煌めき」两个意象的收束——最华丽的终点。

### 2.2 硬性约束

> **禁止蓝紫配色。** 不出现任何蓝、靛、青、紫色相及其渐变。
> 允许的彩色只有红，且红色仅用于交互反馈，不做大面积铺色。

### 2.3 核心视觉符号

从 LOGO 与设定图提取三个反复出现的符号：

**① 断裂圆环（Broken Ring）**
LOGO 中被上下两段弧切开的圆。主识别符号。
用法：页面转场、加载进度、图片裁切遮罩、hover 时弧段旋转张开。

**② ECG 波形线（心电波）**
设定图右下角 RIPJune 文字旁的波形线。
用法：全站分隔线、时间轴、音频播放进度、Footer 签名。

**③ 斜切 −18°**
LOGO 中 RIPJUNE 字样的倾斜角度。
用法：标题、标签、按钮的文字倾斜，与水平正文形成张力。

### 2.4 排版骨架

设定图的信息排版是全站范式，**每个页面页首统一使用**：

```
RIPJune                        ← 极粗黑体 · 斜切 −18° · 字间距拉开
破軍星の終焉煌めき              ← 明朝体 · 竖排 · 从右向左
ほんんせい。                     ← 极小字号 · 字间距极大 · 低对比

Vocaloid
Music Creator
mekichann                      ← 极小无衬线 · 逐行堆叠 · 元数据
```

### 2.5 图片处理

**原则：作品封面不下载，全部远程直链；本地只保留品牌/角色衍生图。**

| 类型 | 处理 |
|---|---|
| 作品封面（bilibili `pic`） | **不下载**；`https://i0.hdslb.com/...` 直链，卡片加 `@480w_270h_1c.webp`、详情加 `@960w_540h_1c.webp`；**必须** `referrerpolicy="no-referrer"`，否则 B 站返回 403 |
| 作品封面显示 | 灰度常态；hover 去灰度 + 极淡红色调；`loading="lazy" decoding="async"`，16:9 `aspect-ratio` 防抖动 |
| 封面兜底 | 加载失败/作品下架 → 本地断裂圆环占位图 + `NO SIGNAL`，不留空白 |
| 角色立绘、设定图 | `ME/人物设定.png` 单图，灰阶 + `background-position` 裁切；不切成 10 个文件 |
| LOGO / 头像 | `ME/LOGO.png`（透明）、`ME/头像.png`；保持黑白，不做灰度；暗底用 invert |
| 内嵌播放器 iframe | 默认 `grayscale(1)`，hover 恢复彩色 |
| 全站 | 图片统一加极细边框（1px 半透明白），像贴在设定页上的照片 |
| OG / favicon | 由 `ME/YT头图.png`、LOGO 生成；**不用** B 站封面做 `og:image`（爬虫可能被 403） |

## 3. 信息架构（页面清单）

### 3.1 站点地图

**一条连续长页 + 作品详情页 + 404**，三语各一套；主界面的 5 屏按顺序堆叠，滚动不会在屏与屏之间「到底」。

```
/                 TOP → PROFILE → WORKS → SOCIAL → ARCHIVE（连续长页）
├── #top          TOP           视觉冲击 + 精选内容
├── #profile      PROFILE       你是谁 + SNS
├── #works        WORKS         所有作品（核心）
├── #social       SOCIAL        社交与联系
├── #archive      ARCHIVE       角色设定档案（10 分区）
├── /works/:bv    WORK DETAIL   单个作品详情（独立页，BV 号参数）
└── /404          NOT FOUND     风格化兜底
```

**三语路径**：`/`（日）· `/zh/`（中）· `/en/`（英）；每语一条完整连续长页。
**阅读顺序**：TOP → PROFILE → WORKS → SOCIAL → ARCHIVE；**Footer 只在 ARCHIVE 之后出现一次**。
**详情路径**：`/works/<BV>`（日）· `/zh/works/<BV>` · `/en/works/<BV>`。

### 3.2 屏职责一览

| # | 屏 | 锚点 | 一句话职责 | 权重 |
|---|---|---|---|---|
| 1 | **TOP** | `/#top` | 用一屏说清「我是谁」，再往下是精选内容 | ★★★ |
| 2 | **PROFILE** | `/#profile` | 三语自述 + 立绘 + 技能 + 合作意向 + SNS | ★★☆ |
| 3 | **WORKS** | `/#works` | **站点核心**，按身份分区的 47 部作品档案 | ★★★ |
| 4 | **SOCIAL** | `/#social` | 平台入口 + 联系 + 版权声明 | ★★☆ |
| 5 | **ARCHIVE** | `/#archive` | 角色设定拆解，10 个分区 | ★★☆ |
| — | **WORK DETAIL** | `/works/:bv` | 单个作品完整信息 + 播放 + Credits | ★★☆ |
| — | **404** | `/404` | 断链兜底 | — |

### 3.3 全站导航

**Header**（固定顶部，滚动时收窄 `64px → 48px`）

```
[断裂圆环小图标] RIPJune   WORKS  PROFILE  SOCIAL  ARCHIVE   [𝕏][▶][n][b]   [ 中 / 日本語 / EN ]
```

- Logo 简化为「断裂圆环 + RIPJune」小图标，点击回 `#top`
- **SOCIAL 提到第 3 位**；导航项是锚点，滚动时高亮当前屏
- **SNS 图标行**（𝕏 / YouTube / niconico / bilibili）常驻：≥1280px 显示，以下收进汉堡菜单；16px 线性图标、无品牌色、`aria-label`、`rel="me noopener"`
- 语言切换器常驻右上，切换时保留当前 section（`/#works` → `/zh/#works`）

**Footer**（整条长页末尾只出现一次）

```
───────────────────────────────← ECG 波形线

破軍星の終焉煌めき / メキチャン
RIPJune — Vocaloid Music Creator
```

## 4. 设计系统

### 4.1 色彩

> 灰阶为主，红色仅作交互反馈。**无蓝无紫。**

#### 基础灰阶（明→暗）

| Token | 值 | 用途 |
|---|---|---|
| `--c-white` | `#FFFFFF` | 页面底色（默认亮色）、反色文字 |
| `--c-gray-100` | `#F2F2F3` | 分区块背景 |
| `--c-gray-200` | `#D8D8DC` | 分割线、次要边框 |
| `--c-gray-300` | `#A8A8B0` | 占位文字、禁用态 |
| `--c-gray-400` | `#6E6E78` | 辅助说明文字 |
| `--c-gray-600` | `#3A3A42` | 次级面板背景 |
| `--c-gray-800` | `#1A1A1E` | 深色区块背景 |
| `--c-black` | `#08080A` | **页面主墨色**、正文 |
| `--c-ink` | `#000000` | 纯黑，仅用于 LOGO 与极端对比 |

#### 强调红

| Token | 值 | 用途 |
|---|---|---|
| `--c-red` | `#CE1126` | **唯一强调色** |
| `--c-red-dim` | `#8E0C1B` | 红色悬停/按下 |
| `--c-red-glow` | `rgba(206,17,38,.28)` | 红色光晕、focus ring |

#### 用法纪律

- 红色**只**用于：链接 hover、当前导航项、播放按钮、focus ring、正在播放的波形进度
- 红色**不**用于：大面积背景、标题文字、装饰色块
- hover 时红色只出现在**细线条和小图标**上，不整块翻红

### 4.2 字体

| 角色 | 字体 | 用途 |
|---|---|---|
| **Display** | `Archivo Black` / `Anton` | RIPJune、页面大标题，斜切 −18° |
| **JP Mincho** | `Shippori Mincho` / `Noto Serif SC` | 破軍星の終焉煌めき、竖排日文、签名 |
| **CN Serif** | `Noto Serif SC` | 中文自述（保证简体字形完整） |
| **CN** | `Noto Sans SC` | 中文正文 |
| **EN** | `Inter` | 英文正文、元数据 |
| **Mono** | `JetBrains Mono` | BPM、调性、时间戳、ID 等标注 |

**处理原则**
- Display 字体必须 `transform: rotate(-18deg)` 或 `skewX(-18deg)`
- 日文标题用 `writing-mode: vertical-rl` 竖排
- 极小字号元数据 `10–11px` + `letter-spacing: .3em` 全大写
- 中文正文 `line-height: 1.9`

### 4.3 间距与栅格

- 基础单位 `8px`，全部间距取 8 的倍数
- 桌面端 12 列栅格，最大内容宽 `1280px`，左右留白 `48px`
- 平板 8 列，移动 4 列
- 区块垂直间距 `120px`（桌面）/ `72px`（移动）
- 圆角统一 `2px`（近乎直角，呼应设定图的硬边分割线）

### 4.4 图形元素

| 元素 | 规格 |
|---|---|
| **断裂圆环** | SVG，2 段弧，缺口 `120°`，线宽 `2px`，hover 时旋转 `90°` |
| **ECG 波形** | SVG path，周期 `240px`，线宽 `1.5px`，用作分隔与签名 |
| **分割线** | `1px` 实线 `--c-gray-200` |
| **分割号** | 文字 `—` 或 `/`，作为标题与内容的连接符 |
| **角标** | 右上角小方块，标注作品编号（如 `NO.004`） |

### 4.5 响应式断点

| 断点 | 宽度 | 处理 |
|---|---|---|
| 桌面 | `≥1280px` | 完整栅格，竖排日文显示 |
| 平板 | `768–1279px` | 8 列，竖排日文转横排 |
| 移动 | `<768px` | 4 列，单栏，LOGO 斜切减小到 −12° |

## 5. 动效规范

> 原则：**动而不炫技。** 简洁中显高级。
> 动效分四个落点：**背景、顶部标签栏、正文卡片、鼠标**。
> 每处只做一件事，用最轻的方式做。

### 5.1 动效分工（四类常驻 + 屏间衔接）

| 落点 | 作用 | 频率 | 强度 |
|---|---|---|---|
| **背景动效** | 让页面「有生命」 | 常驻循环 | 中 |
| **顶部标签栏动效** | 指示当前位置 | 交互触发 | 中，快速明确 |
| **正文卡片动效** | 分隔内容 + 悬停反馈 | 滚动触发 + 悬停 | 中低 |
| **鼠标动效** | 制造「在场感」 | 跟随指针 | 低，只在局部 |
| **屏间衔接** | 指示「下一屏开始」 | 滚动触发 | 低，一次只做一处 |

**通用约束**
- 缓动统一 `cubic-bezier(.16,1,.3,1)`（起步快、收尾极缓）
- 入场 `480ms` · 交互 `240ms` · 背景循环 `≥20s`
- **禁止**：弹跳、缩放超过 `1.05`、旋转超过 `10°`、粒子/光斑跟随、视差滚动
- 所有动效在 `prefers-reduced-motion: reduce` 下关闭
- 屏间衔接是一次性入场，不进入背景循环；规则见 5.8

---

### 5.2 背景动效

背景不是静止的，但**不能太明显抢占主位**——观众说不出它在动，只觉得「页面是活的」。

####① ECG 底纹（全局，最重要）

- 页面最底层铺一层 **1px 灰阶 ECG 波形**（`--c-gray-200`，透明度 `.35`）
- 波形**横向极缓慢平移**：`60s` 循环，移动距离 = 一个波形周期
- 这是全站动效的基调来源——呼应设定图的心电波
- **不可**加红色、不发光、不随鼠标变化

#### ② 断裂圆环·背景版（仅 TOP / ARCHIVE）

- 一个直径 `min(90vw, 900px)` 的巨大断裂圆环，`1px` 线宽，透明度 `.06`
- 置于页面背景，两段弧**各自缓慢自转**：`120s` / `160s` 一圈（比首屏那个更慢）
- 作为背景纹理存在，**不响应鼠标**

#### ③ 纸面颗粒（静态）

- 全站叠一层极淡噪点纹理（SVG feTurbulence生成，`opacity .025`）
- **完全静态**，用于消除大面积纯白的塑料感，让白底「像纸」
- 这是质感的关键，成本极低

#### ④ 红色呼吸点（仅 TOP 首屏）

- ECG 波形上有一个 `2px` 的红点，沿波形缓慢移动，`9s` 循环一圈
- 出现频率极低，作用是让视线有落点

---

### 5.3 顶部标签栏动效

WORKS 页的分类标签栏是全站最重要的导航，动效分三段。

#### ① 当前项指示器（切换时）

```
ALL 47 ──── 二创剪辑 33 ──── VOCALOID 4 ──── 原创曲 0 ──── 搬运 1 ──── 其他 9
        ▔▔▔▔
```

- `n1–n4` 由标注文件自动计数，动画只关心「当前项 / 目标项」两段；当前实际计数为 33 / 4 / 0 / 1 / 9

- 切换标签时，**红色下划线**从旧项底部滑向新项
- 时长 `320ms`，`cubic-bezier(.16,1,.3,1)`
- 用一条绝对定位的 `<span>` 移动 + `width` 过渡，**不做逐项淡入淡出**（那样很廉价）

#### ② 悬停：波形延长

- 悬停某个未选中标签时，其下方的**灰阶波形线**从 `24px` 延长到 `48px`
- 同时该标签的波形**加深一档**（`--c-gray-300` → `--c-gray-600`）
- 时长 `240ms`

#### ③ 标签计数呼吸

- 每个标签右侧的数字（`7`）用等宽字体
- 切换分类时数字做一次**极短的缩放脉冲**：`scale(1) → 1.12 → 1`，`260ms`
- 只在数字上做，不影响标签文字

#### ④ 顶部 Header

- 滚动超过 `80px` 时高度从 `64px` 收到 `48px`
- 底部1px 分割线淡入
- 语言切换器 hover：下划线从左推进

### 5.4 正文卡片动效

正文内容**切分为卡片**——这是本站排版的核心手法（呼应设定资料集把信息贴在版面上的感觉）。

#### 卡片基础样式

```
┌─────────────────────────────────────┐
│ NO.001                全部制作       │  ← 顶栏：编号 + 参与度
│                                     │
│  标题文字                           │  ← 正区
│                                     │
│  ─────                              │  ← 底部ECG 细线
│  圆桌动漫 · 2026-05-03 · 1.2w 播放   │  ← 元数据行
└─────────────────────────────────────┘
```

- 底色 `--c-white`，1px 边框 `--c-gray-200`
- **无阴影**（阴影 = 廉价）、**无圆角**（2px 呼应硬边）
- 内部留白 `24px` / `32px`
- 卡片之间间距 `24px`

#### ① 滚动入场

- 卡片进入视口时：`opacity 0 → 1` + `translateY(20px) → 0`
- 时长 `480ms`
- **同组卡片依次延迟 `70ms`**（最多 6 张后不再累加）
- 卡片内元素一起动，**不做内部元素的分层飞入**（太花）

#### ② 悬停：卡片响应

| 元素 | 变化 | 时长 |
|---|---|---|
| 卡片整体 | `border-color` → `--c-black`，向右位移 `4px` | `240ms` |
| 封面图 | `grayscale(1) → .15` | `240ms` |
| 底部 ECG 线 | 从左向右**重新描画一次**（`stroke-dashoffset` 动画） | `420ms` |
| 标题 | 下划线从左推进 | `240ms` |
| 播放键 | 细线三角展开成实心 | `200ms` |

> 卡片位移 `4px` 而非 `scale`——位移比缩放克制，也不会让边框变形。

#### ③ 卡片序号

- `NO.001` 等宽字体贴在卡片右上
- 悬停时数字**颜色由灰变黑**（`--c-gray-400` → `--c-black`），不做位移

### 5.5 鼠标动效

**不做自定义光标**（`cursor: url()` 在跨平台和移动端都不可靠）。
改用「局部响应」——鼠标经过时，**那一块区域**有反应。

#### ① 内容区·光标牵引细线（全局，签名动效）

- 鼠标移动时，其后拖一条**1px 红线**，长度 `56px`
- 线是 SVG path，两点跟随指针，带 `140ms` 延迟跟随（不是死跟，略有滞后感）
- 鼠标停下时线自然收回消失
- **仅在内容区**（`.content` 容器内）生效，Header/Footer 不生效
- 鼠标移出内容区即隐藏

> 这就是「鼠标的特效」——不是换指针样式，而是指针**拖尾**。

#### ② 卡片磁性微吸（仅 WORKS 卡片）

- 鼠标进入卡片时，卡片内容层向鼠标方向**位移最多 `6px`**
- 位移量 = `(鼠标位置 − 卡片中心) × 0.02`，并被`6px` 截断
- 移出时`240ms` 弹回原位
- 位移的是**内容层**（标题+图），卡片边框不动——产生「内容浮在卡上」的层次

#### ③ 断裂圆环·开合

- 鼠标进入断裂圆环元素时，两段弧**各向外旋转 `42°`**，缺口张开
- 时长 `420ms`，`--c-red` 变红
- 离开时收回

#### ④ 文字·下划线推进

- 所有链接 hover：下划线从左推进，`240ms`
- 元数据项（年份、编号）hover：数字**后移 `2px`**

#### ⑤ 指针位置反馈点（仅 ARCHIVE 灯箱）

- 灯箱打开时，左右两侧出现**红点 + 「PREV」「NEXT」文字**
- hover 时红点放大 `1.4`，文字右移 `4px`

---

### 5.6 「不显得廉价」的五条底线

1. **所有循环动效周期 ≥ 20s**——快 =廉价
2. **同时出现的动效元素 ≤ 3处**——满屏动 = 廉价
3. **位移距离 ≤ 8px，缩放 ≤ 1.05**——大幅运动 = 廉价
4. **错落时序**——标题先、正文延迟 `80ms`、卡片间 `70ms`；同时出现 = 廉价
5. **缓动只用一个**——`cubic-bezier(.16,1,.3,1)`，不要 ease-in 也不要 linear

---

### 5.7 无障碍与降级

- `prefers-reduced-motion: reduce`：**全部动效关闭**，内容直接可见
- 背景 ECG、圆环自转用 CSS `animation`，reduced-motion 下 `animation: none`
- 鼠标牵引线用 JS 监听 `pointermove`，reduced-motion 下不挂载
- 环境动效在 `document.hidden` 时 `animation-play-state: paused`
- 移动端（触摸设备）**完全禁用**鼠标牵引线与磁性吸附
- 连续长页：`html { scroll-behavior: smooth; }` 在 reduced-motion 下改 `auto`；**不劫持 wheel/touch**
- 锚点偏移由 `scroll-padding-top: var(--header-h)` 处理；文档开头提供 skip-link，可直接跳到 5 屏
- `End` 键仍可到文档末尾；不困住焦点

### 5.8 屏间衔接（连续界面）

> 主界面是一条长页，不是 5 个独立页面。屏与屏之间**没有页尾**，只有一条「屏门」；整条文档只在 ARCHIVE 结束后出现一次 Footer。

#### ① 屏门（ScreenGate）

每屏末尾放一个 `<ScreenGate>`：

```
───────────────────────────────← 1px ECG
02 / PROFILE            ↓ 続く
```

- 左侧：下一屏编号 + 英文名（Mono 11px，`letter-spacing: .3em`）
- 右侧：`↓ 続く` / `SCROLL`（三语）；整块可点击，点击滚动到下一屏
- 屏门之后**直接**是下一屏的页首，不插入 Footer、不插入空白屏
- 屏与屏之间用 `--c-white` / `--c-gray-100` 交替 + 1px 分割线，暗示「新界面」

#### ② 入场

- 下一屏页首进入视口（`rootMargin: -20%`）时：`opacity 0→1`、`translateY(8px)→0`，`480ms`
- 屏门的 ECG 线从左向右描画一次，`420ms`
- 同屏卡片沿用 5.4 的 70ms 递延
- **不做**整屏滑动/覆盖/缩放；不劫持滚动；不做 scroll-snap
- 一屏内同时只允许一处屏门入场动效

#### ③ 导航与 URL

- 导航项是锚点：`#top` `#profile` `#works` `#social` `#archive`
- 滚动时用 IntersectionObserver 更新当前项（红色下划线），`history.replaceState` 同步 hash
- 直接打开 `/#works` 时按 hash 定位；`scroll-padding-top: var(--header-h)` 抵消固定 Header
- 浏览器后退/前进按 hash 恢复；不因滚动刷历史记录

#### ④ 作品详情转场

- 点卡片 → `/works/<BV>`（独立页）
- 用 Astro ClientRouter + View Transition：封面共享元素 `view-transition-name: work-cover`，`480ms`
- 返回：`history.scrollRestoration = 'manual'` + `sessionStorage` 记录 `scrollY`，回到 WORKS 原位置
- 详情页有自己的 Header/Footer；主长页的 Footer 仍只有一次

#### ⑤ 性能与降级

- 47 张远程图 `loading="lazy"`；section/card `content-visibility: auto`
- 封面固定 16:9，防 CLS
- `prefers-reduced-motion: reduce`：关闭屏门入场、平滑滚动、详情共享元素动画
- 移动端：屏门可点击；不依赖 hover；SNS 图标常驻

#### ⑥ 文档终点

ARCHIVE 之后是唯一的终点：

```
───────────────────────────────
END OF TRANSMISSION / 信号终了
終焉は、最も美しく煌めく。
[Footer]
```

- 这是整条长页唯一「到底」的位置；之前任何一屏结束都不会出现 Footer

### 7.5 作品数据管线（videos.json + view API + 手动标注）

> **一句话**：`videos.json` 只负责「有哪些作品、BV 号、发布时间字符串、播放/弹幕快照」；作品详情一律用 `x/web-interface/view?bvid=<BV号>` 逐条拉取；分类、参与度覆盖、Credits 的人工部分写进 `data/works.manual.yaml`。构建期只读本地快照，不做运行时请求。

#### 7.5.1 数据源与合并顺序

| 阶段 | 接口/文件 | 取什么 |
|---|---|---|
| 清单 | `API_Program/videos.json`（手动运行 `bili_all_videos.py`） | `bvid`、`created_str`（直接显示，不转时区）、`length`、`play`、`video_review` |
| 详情 | `https://api.bilibili.com/x/web-interface/view?bvid=<BV号>` | `title`、完整 `desc`、`pic`、`duration`、`pubdate`、`owner`、`staff`、`stat`、`copyright`、`pages[].cid` |
| 主页 | `https://api.bilibili.com/x/web-interface/card?mid=1016873598` | `card.fans`、`like_num`、`archive_count` |
| 总计 | `https://api.bilibili.com/x/space/upstat?mid=1016873598` | `archive.view`、`likes`（需 SESSDATA） |
| 人工 | `data/works.manual.yaml` / `data/people.yaml` | 分类、参与度覆盖、补充 Credits、精选、人名链接 |

合并优先级：**view > vlist**；**人工 > 自动**。

- vlist 的 `description` 会被 B 站截断（如 BV15fbR6pE7H 只返回约 250 字），**简介必须用 view 的 `desc`**。
- `video_review` 与 view 的 `stat.danmaku` 合并为同一个「弹幕」指标：`danmaku = stat.danmaku ?? video_review`；vlist 值只作快照/对账，不单独展示。
- `created_str` 直接使用；`pubdate` 只用于排序。
- `stat` 六项：`view / like / coin / favorite / danmaku / reply`；另保留 `share`。

### 7.10 左侧收起式迷你播放器

> 需求：**不放大型播放器，收起在页面左侧边缘**。

**形态**：贴在视口左边缘的一个 `48px × 48px` 的小方块（固定定位，`z-index` 高于内容）。

**收起态**（默认）
- 只显示**断裂圆环图标**，内部一个极小的红色圆点表示「可播放」
- hover：圆环张开 `42°`，图标旁向右浮出标签 `RIPJUNE`+ 正在播放的曲名
- 视觉上不抢主体，1px 边框，`--c-white` 底

**展开态**（点击后从左边缘滑出 `320px` 宽的面板）
- 只在有播放内容时启用；**当前没有原创曲**，因此面板内容为「暂无播放内容 · NO SIGNAL」
- 结构预留：
  ```
  ├─ 封面（灰度）
  ├─ 曲名 + 音源
  ├─ 波形进度条（红点为播放头）
  ├─ ◀◀ ▶ ▶▶ ｜00:00 / 02:39
  └─ [ × ] 收起
  ```
- 点击面板外或`×` 收起，滑回左边缘

**动效**
- 收起 → 展开：面板 `translateX(-100%) → 0`，`320ms`，`cubic-bezier(.16,1,.3,1)`
- 展开态下方的页面内容**不移动**，面板以浮层覆盖
- 移动端：收为屏幕底部 `56px` 高的迷你条，点击向上弹出

**约束**
- 面板底色 `--c-black`，文字白色——与全站白底形成唯一一处反色
- 红色仅用于播放头和进度条，不整块铺红
- 当前无音频文件，先只做结构与视觉，不接播放逻辑

### 7.11 OG Image / 分享卡片

> 已定：用 `ME/YT头图.png` 作为底图，`scripts/prepare-assets.mjs` 在构建前生成 `public/og-image.jpg`；不再需要手动作图。

#### 用途

当有人把你的网站链接发到X、Twitter、Discord、Slack、Telegram 或微信时，
这些平台会抓取页面里的 OG 标签，在链接卡片上渲染一张预览图。

也就是说：**OG Image 就是你的链接在别人聊天框里的样子。**

对Vocaloid 创作者来说，这张图会出现在：
- 转发自己作品时（作品链接卡片）
- 被人推荐到群里时
- 搜索引擎结果里

它的实际曝光率往往**高于网站首屏**——很多人是从卡片点进来的。

#### 技术要求

| 项 | 要求 |
|---|---|
| **尺寸** | `1200 × 630 px`（唯一稳定支持的尺寸） |
| **比例** | 约 `1.91:1` |
| **格式** | `PNG` 或 `JPG`，文件大小 **< 300KB**（超出会被部分平台丢弃） |
| **文件位置** | 仓库 `public/og-image.jpg`，线上路径 `https://<域名>/og-image.jpg` |
| **在HTML 中的声明** | 每页`<head>` 内都要有（见下方代码） |

```html
<!-- 每页 head 里都要写全这四行 -->
<meta property="og:type"        content="website" />
<meta property="og:title"       content="RIPJune — Vocaloid Music Creator" />
<meta property="og:description" content="破軍星の終焉煌めき / メキチャン。二创剪辑与 Vocaloid 歌唱。" />
<meta property="og:image"       content="https://rftgcftctchcg.github.io/hagunseinoshuuenkirameki/og-image.jpg" />
<meta property="og:url"         content="https://rftgcftctchcg.github.io/hagunseinoshuuenkirameki/" />
```

**补充建议**
- 再加 `twitter:card` = `summary_large_image`，让 X 也显示大图
- 中/日/英三语页可以用**不同的 og:title文字**，但**共用同一张图**（省事，且视觉一致）
- `og:description` 控制卡片文案，约 **60–120 字符**，超出会被截断

#### 设计要求（沿用本站视觉规范）

- **背景**：`--c-white` 纯白，或反过来做一张 `--c-black` 的「暗色款」
- **主视觉**：断裂圆环 + 斜切 RIPJUNE（与 LOGO 同一套元素）
- **必备文字**：`RIPJune` + `終焉は、最も美しく煌めく。`
- **辅助信息**：三行小字 `Vocaloid Music Creator` / `メキチャン` / `破軍星の終焉煌めき`
- **底部**：一条 ECG 波形线（呼应全站符号）
- **禁止**：蓝紫配色、大面积红底、超过两种字体
- 文字要留足安全边距（各边 ≥ `80px`），因为部分平台会裁掉边缘

#### 生成方式

- 底图：`ME/YT头图.png`（2048×1152），中心裁切到 `1200×630`
- 叠加：`RIPJune` + `終焉は、最も美しく煌めく。` + 三行元数据 + ECG 线
- 输出：`public/og-image.jpg`，<300KB
- 暗色备选：`og-image-dark.jpg` 可选，非必需
- 每部作品**不单独做分享图**；详情页用同一张默认图，`og:title` / `og:description` 按作品动态生成
- `og:image` 必须是本地 URL，**不要**用 bilibili 封面（爬虫会被 403）

> 放置位置：`public/og-image.jpg`——放在这个目录才会被原样输出到网站根路径。

- 语义化标签：`header` / `nav` / `main` / `section` / `article` / `footer`
